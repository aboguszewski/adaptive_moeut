\section{Introduction}
\textit{Universal Transformers} (UTs) are not a new idea \cite{ut}.
They are a variation of the \textit{Vanilla Transformer} (VT) \cite{transformer} architecture that achieves network depth not via stacking multiple transformer blocks, but rather reusing the same blocks in a loop.
They are the spiritual ancestor of \textit{Recurrent Neural Networks} (RNNs) in the transformer paradigm and are usually designed either as pure cycles or cycles with additional initial and final layers (see Figure~\ref{fig:ut-designs}).

Proponents of this architecture argue that they generalize better - that the built-in recursion allows the models to decompose structured problems, and generalize to longer sequences \cite{moeut}.
However the weight-sharing also introduces some scaling-related problems, because a UT that loops $N$ times is equivalent in depth to a $N$ layer VT, but only has $\frac{1}{N}$ parameters.
One of the ideas to combat this issue is to make the UT's layer $N$ times wider, which would result in a usually prohibitive jump in compute and memory requirements.
Another approach is to modify the UT's architecture to introduce some sparsity like in \textit{Mixture-of-Experts} (MoE) \cite{moe}.
This results in a larger parameter count that is arbitrarily scalable, while fixing the compute and memory requirements.

\textit{Mixture-of-Experts Universal Transformer} (MoEUT) \cite{moeut} is a UT architecture that injects sparsity to both the attention computation via \textit{SwitchHead} \cite{switchhead}, and the feedforward layer via $\sigma$-MoE.

In this work we attempt to extend the MoEUT design with \textit{Adaptive Compute Time} (ACT) by using the Stick-breaking Halting algorithm proposed in the \textit{Sparse Universal Transformer} \cite{sut}.

\section{Baseline Models}

To establish reference points for the Fully Adaptive MoEUT we train two
parameter-matched baselines: a standard dense Transformer and a standard MoEUT.
Both are decoder-only autoregressive language models that share the same
tokenizer (a SentencePiece BPE vocabulary of $8{,}192$ tokens), the same model
dimension ($d_{\text{model}}=512$), tied input/output embeddings, rotary
positional embeddings (RoPE) \citep{rope}, and a maximum context
length of $2{,}048$ tokens. Tying the embeddings and fixing the vocabulary makes
the $\sim$33.6M \emph{non-embedding} parameters the only point of difference, so
any quality or efficiency gap reflects the architecture rather than capacity.

\paragraph{Dense Transformer.} The dense baseline is a standard pre-LN
decoder-only Transformer \citep{ut} with eight layers.
Each layer combines causal multi-head self-attention (16 heads
of dimension 64, i.e.\ a $1{,}024$-dimensional attention inner space) with a
two-layer ReLU feed-forward network using the standard $4\times$ expansion
($d_{\text{ff}}=2{,}048$). This model is the backbone of the comparison: following
\citet{moeut} (\S3), the MoEUT
configuration is then chosen to match its parameter count.

\paragraph{MoEUT.} The MoEUT baseline replaces the dense stack with a Universal
Transformer that combines extreme weight sharing with two forms of sparsity.
Rather than eight unique layers, it uses a group of $G=2$ distinct blocks that
are applied repeatedly for $R=n_{\text{layers}}/G=4$ iterations, yielding the
same eight layer applications but only two unique parameter sets. Within each
block, the feed-forward network is a $\sigma$-MoE \citep{sigmamoe}
with $N_E=112$ experts of width 128, of which only $K=8$ are activated per token
(an active hidden width of $8\times128=1{,}024$); the attention is a SwitchHead
mixture-of-experts \citep{switchhead}
with four heads of dimension 128, $N_A=3$ value/output experts and $K_A=2$ active
per head. A small entropy regularizer on the routing distributions
($0.01$ for the feed-forward experts, $0.001$ for the attention experts)
stabilizes MoE training. Crucially, although MoEUT is parameter-matched to the
dense model, only a sparse subset of its experts is active for any given token,
which is the property the adaptive variant aims to exploit.

\paragraph{Training setup.} Both models are trained from scratch under an
identical regime on a LAMBADA-decontaminated subset of the Colossal Clean
Crawled Corpus (C4) \citep{c4}; contamination is removed by dropping any C4
document that shares a $13$-gram with a LAMBADA passage. We optimize the
cross-entropy language-modeling loss with AdamW ($\beta=(0.9,0.95)$, weight decay
$0.1$) at a peak learning rate of $3\times10^{-4}$ with a $1{,}000$-step warmup
and cosine decay, gradient clipping at $1.0$, for $100{,}000$ steps of
$32\times512=16{,}384$ tokens ($\approx 1.6$B tokens total). For MoEUT the
entropy regularization term is added to the loss. All runs are carried out in
\texttt{fp32}.

\section{Baseline Evaluation}

We evaluate both baselines zero-shot on two standard benchmarks. On LAMBADA
\citep{lambada} we report last-word \emph{accuracy} (the model must
greedily predict every token of the final word) and target-token
\emph{perplexity}. On HellaSwag \citep{hellaswag} we report
\emph{accuracy} under the length-normalized scoring rule, selecting the candidate
ending with the lowest mean per-token cross-entropy. To compare efficiency we
also benchmark steady-state inference, reporting per-forward latency and
throughput; both models are timed on the same GPU at the same precision
(\texttt{fp32}) with discarded warmup iterations and CUDA synchronization, so the
wall-clock gap reflects kernel efficiency rather than a difference in nominal
FLOPs. Results are summarized in Table~\ref{tab:baselines}.

The idea behind UT is to introduce extreme weight sharing into the traditional transformer by repeatedly processing tokens with a single transformer block instead of having multiple single-use blocks. MoEUT tries to improve the efficiency of a basic UT, by introducing Mixture-of-Experts in the feedforward networks \citep{moe} as well as the multihead attention mechanism \citep{switchhead}.


% We want to introduce Adaptive Compute Time (ACT) into the MoEUT architecture both at the token and loop level. MoEUT, as presented in the original paper, has a fixed number of loops where every loop processes every token. Every query gets the same amount of compute. The idea of ACT is that different queries require different amounts of compute e.g. we could get away with allocating less compute to easy queries and utilizing those savings for more difficult queries.


% In the case of UTs, ACT could mean adjusting the number of loops that the query goes through before producing an answer. This idea is explored in the LoopFormer and Sparse Universal Transformer \citep{sut} papers. This is what we refer to as loop level ACT. Another approach would be to adjust the amount of tokens that are processed in each loop. This idea is explored in the Mixture-of-Recursions \citep{mor} paper and we refer to it as token level ACT.


% As far as we know the two approaches were never combined - papers mentioned above either fixed the number of loops and adjusted the number of tokens processed (token-level ACT) or fixed the number of tokens processed and adjusted the number of loops (loop-level ACT). We would like to see if implementing both of them within a MoEUT would result in compute savings without sacrificing the  quality of the model.
